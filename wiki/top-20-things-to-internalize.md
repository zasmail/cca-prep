# Top 20 Things to Internalize

*The highest-leverage facts, patterns, and positions across the wiki — ranked by interview leverage (how likely you are to be probed on it and how much a crisp answer signals depth). Each is 1–3 sentences with a source. Drill these the night before.*

---

1. **Guarantee vs. preference is the first question of any agent design.** Anything that must be guaranteed goes in deterministic code — hooks, schema validation, prerequisite gates, exit-code checks — never in a prompt, because CLAUDE.md and system instructions are advisory and decay as context fills. This is the single most-tested CCA-F concept and the root of anti-pattern #3. ([enforcement-reliability.md](enforcement-reliability.md); [blog-claude-code-best-practices](../research/notes/blog-claude-code-best-practices.md))

2. **Autonomy is earned through verifiability, not granted by prompt.** The safe autonomy level equals how well the agent can check its own work; that's why coding (tests/compiler) and deep research (search-and-synthesize) hit full autonomy first, while money movement keeps a gate. "Stop babysitting your agents" means give Claude a self-verification loop so the human stays out *until the work is actually done*. ([enforcement-reliability.md](enforcement-reliability.md); [stytch-agent-ready-ep8](../research/notes/stytch-agent-ready-ep8.md), [cwc-stop-babysitting](../research/transcripts/cwc-stop-babysitting.md))

3. **Verifiability, not specifiability, is the deployment gate.** Karpathy's sharpest architectural claim: LLMs automate what can be *verified*, not merely what can be *specified* — the first question for any agent project is whether the task has an automatic reward signal. Capability is jagged (100k-line refactor vs. trivial commonsense failure), so ask if the task sits "on the model's rails." ([karpathy-mental-models.md](karpathy-mental-models.md); [karpathy-sequoia-recap](../research/notes/karpathy-sequoia-recap.md))

4. **Context is the scarce resource, and context rot is why.** Bigger windows don't remove the constraint — n² pairwise attention plus thin training exposure to long sequences means accuracy *slopes down gradually* as the window fills (not a cliff, which is why it gets ignored until the agent "forgets"). Treat token budget as a first-class design constraint from day one. ([context-engineering.md](context-engineering.md); [blog-context-engineering](../research/notes/blog-context-engineering.md))

5. **Grade the outcome, not the path.** Non-deterministic agents find valid alternate routes; scoring the turn-by-turn trajectory penalizes correct behavior and rewards overfitting — check the final state of the world (did the DB update, did tests pass). Prefer deterministic code graders where possible; reserve LLM-as-judge for genuinely subjective quality and always calibrate against humans. ([evals.md](evals.md); [blog-demystifying-evals](../research/notes/blog-demystifying-evals.md))

6. **pass@k vs. pass^k answer different product questions.** A coding agent where any one success suffices optimizes pass@k; a customer-facing agent that must behave consistently *every* time optimizes pass^k — and 75% single-trial reliability is only ~42% over three consecutive turns (0.75³). Reporting aggregate accuracy hides the instability that matters. ([evals.md](evals.md), [enforcement-reliability.md](enforcement-reliability.md); [blog-demystifying-evals](../research/notes/blog-demystifying-evals.md))

7. **Reliability compounds multiplicatively, so put gates between steps.** A 95%-reliable step chained ten times succeeds end-to-end only ~60% of the time; long-horizon agents fail on "nines of reliability," not context exhaustion. Verification gates and resumable checkpoints stop early errors from cascading — a small failure early can send the whole trajectory off course. ([enforcement-reliability.md](enforcement-reliability.md); [dwarkesh-sholto-trenton](../research/notes/dwarkesh-sholto-trenton.md), [blog-multi-agent-research](../research/notes/blog-multi-agent-research.md))

8. **A tool is a contract with a non-deterministic reader, not an API endpoint.** The agent may misread arguments, hallucinate them, or ignore the tool — so tool descriptions deserve the same rigor as prompts (Anthropic tuned tools *harder* than the overall prompt on SWE-bench). Never wrap a REST API 1:1; design tools backward from user workflows and model reasoning. ([tool-design-and-mcp.md](tool-design-and-mcp.md); [blog-writing-tools](../research/notes/blog-writing-tools.md), [aiewf-2025-mcp-track](../research/notes/aiewf-2025-mcp-track.md))

9. **Escalate on structure, terminate on stop_reason.** Three valid escalation triggers — explicit customer request, policy gap, capability limit; two traps — sentiment ("sounds angry") and self-reported confidence ("60% sure"), both model-generated signals with no ground truth (anti-patterns #4–5). Terminate the agent loop by checking the API's `stop_reason`, never by parsing natural language for "I'm done"; an iteration cap is a safety net, not the primary control. ([enforcement-reliability.md](enforcement-reliability.md); Project CLAUDE.md)

10. **Progressive disclosure is context engineering, not a feature.** Skills load in three tiers — metadata (always visible) → SKILL.md body (on relevance) → bundled files (on demand) — which is what lets hundreds of skills coexist without context rot. The same economics govern on-demand MCP tool loading: **150,000 → 2,000 tokens (98.7% reduction)** when tool defs load via code execution instead of upfront. ([skills-and-progressive-disclosure.md](skills-and-progressive-disclosure.md), [tool-design-and-mcp.md](tool-design-and-mcp.md); [blog-agent-skills](../research/notes/blog-agent-skills.md), [blog-code-execution-mcp](../research/notes/blog-code-execution-mcp.md))

11. **Most "agent" projects should not be agents — climb the complexity ladder.** Start with a single augmented LLM call plus retrieval and few-shot; go single-shot → agent loop → workflows → multi-agent only when each rung earns its keep on a real eval. Workflows run predefined code paths (predictable tasks); agents let the model direct its own process (open-ended tasks) — autonomy trades latency, cost, and compounding-error risk for flexibility. ([orchestration-patterns.md](orchestration-patterns.md); [blog-building-effective-agents](../research/notes/blog-building-effective-agents.md))

12. **Multi-agent is the top rung and the most expensive — ~15x tokens.** Anthropic's orchestrator-workers research system beat a single agent by **90.2%** but costs ~15x a normal chat (~4x single-agent), so it only pays off for high-value tasks whose subproblems parallelize with loose coupling. It's a poor fit for tightly-coupled work like most coding, where shared context beats parallel surface area; the coordinator manages *all* inter-agent communication — workers never talk directly. ([orchestration-patterns.md](orchestration-patterns.md); [blog-multi-agent-research](../research/notes/blog-multi-agent-research.md))

13. **Token usage explains ~80% of multi-agent performance variance — context strategy *is* performance strategy.** Model choice and tool-call count explain the remaining ~15%. Subagent isolation, code-execution filtering, and just-in-time retrieval aren't hygiene; they're the primary lever — which is also why they cost ~15x and should be reserved for high-value work. ([context-engineering.md](context-engineering.md); [blog-multi-agent-research](../research/notes/blog-multi-agent-research.md))

14. **The human's job moved from writing code to closing the verification loop.** Explore → Plan → Implement → Commit exists to keep a machine-checkable pass/fail signal between "looks done" and "committed" — without it, the human silently *becomes* the verification loop. ~80% of Cherny's sessions start in read-only plan mode; 70–90% of Anthropic's code is Claude-written. ([claude-code-workflows.md](claude-code-workflows.md); [blog-claude-code-best-practices](../research/notes/blog-claude-code-best-practices.md), [yc-inside-claude-code](../research/notes/yc-inside-claude-code.md))

15. **Never self-review in the same session; pair complementary reviewers.** Same-session self-review invites confirmation bias (anti-pattern #9); generation and evaluation belong in separate sessions, and the strongest setup pairs agents with non-overlapping strengths (one catches style, one catches edge cases). ([claude-code-workflows.md](claude-code-workflows.md), [evals.md](evals.md); [blog-claude-code-best-practices](../research/notes/blog-claude-code-best-practices.md))

16. **Aggregate accuracy is a lie — report per-type and per-field.** One blended number hides which document type or field is failing; evaluate by agent archetype (coding needs test execution; conversational needs user-simulation; computer-use must check *backend* state, not just the UI) and, for extraction, per-document-type and per-field (anti-pattern #10). A 0% pass rate across many trials almost always means a broken task/grader, not an incapable model. ([evals.md](evals.md); [blog-demystifying-evals](../research/notes/blog-demystifying-evals.md))

17. **Knowledge should compound, not re-derive.** Classic RAG re-derives an answer from raw chunks cold every query; Karpathy's LLM-wiki has an agent *maintain* a persistent markdown layer of its own distilled synthesis (ingest → query → lint), so knowledge gets cheaper and better over time. LLMs have no episodic memory or sleep-like consolidation, so durable memory is a write-back-and-retrieval problem — skills are the same idea for *procedural* knowledge (Day 30 >> Day 1). ([memory-and-compounding.md](memory-and-compounding.md); [karpathy-llm-wiki](../research/notes/karpathy-llm-wiki.md), [dont-build-agents-build-skills](../research/notes/dont-build-agents-build-skills.md))

18. **≤5 tools per agent; 18+ degrades selection.** Three vectors kill tool selection: too many tools, tool repetition, and mixing domains/instructions (anti-pattern #8). The reconciliation with 5,000-tool marketplaces is "few tools *in context at once*, many available *on demand*" via progressive disclosure — but curation vs. infrastructure is a genuine live disagreement. ([tool-design-and-mcp.md](tool-design-and-mcp.md); [aiewf-2025-mcp-track](../research/notes/aiewf-2025-mcp-track.md))

19. **MCP's value is boring standardization, not novelty — it's LSP for AI.** Open-sourced Nov 2024, JSON-RPC, three primitives (tools, resources, prompts) plus sampling; it solves the M×N integration problem so every client and context provider speak once. "Being boring on stuff like this is good" — standardize internally behind a gateway to centralize auth, rate-limiting, and prompt-injection filtering at one choke point. ([tool-design-and-mcp.md](tool-design-and-mcp.md); [remote-mcps-lessons](../research/notes/remote-mcps-lessons.md), [sed-mcp-soria-parra](../research/notes/sed-mcp-soria-parra.md))

20. **The winning application architecture is connective tissue, not a new tool.** Anthropic's own AI-native sales org keeps the existing stack (Salesforce, Clay, Gong) and uses Claude to thread the seams — shipping connectors + skills together as one "plug-in," with a programmatic human-send-gate on anything customer-facing (the outbox pattern). Don't rip-and-replace the system of record; integrate against it and own the synthesis layer. ([gtm-applications.md](gtm-applications.md); [ai-native-sales-org](../research/notes/ai-native-sales-org.md))

### Number flashcards (memorize cold)

- Cache hit = **10%** of base cost; 5-min TTL = **1.25x** write, 1-hour = **2x**; min is **model-dependent** (512–4,096 tokens; **1,024 for Sonnet 5/Opus 4.8**, 512 for Fable 5/Mythos 5, 4,096 for Opus 4.6/Haiku 4.5) — don't memorize "1024" as universal; up to **4 breakpoints**; prefix order **tools → system → messages**.
- Batch API: max **100,000 requests OR 256 MB**, whichever hits first (not 10,000 — that's a stale figure); **50%** discount; **24-hour** window; results **.jsonl** for **29 days**; **multi-turn conversations and tool use (incl. server tools) ARE supported** — the real unsupported list is narrower: `stream:true`, thread/`store` continuation params, cache hints, `max_tokens:0`, Fast mode.
- Multi-agent: **90.2%** lift, **~15x** tokens vs chat, **~4x** vs single-agent; **~80%** of variance = token usage.
- Evals: start **20–50** real-failure tasks; **~20** queries detected signal (30%→80% swing); CORE-Bench **42%→95%** after grader fix.
- Code execution: **150k→2k** tokens (98.7%). Tool cap **≤5** (18+ fails).
- Context management is a *capability* lever: memory tool + context editing = **+39%** on internal evals ([evolving-claude-apis](../research/notes/evolving-claude-apis.md)).
- Enterprise adoption lags capability **~6 months**; individual devs adopt ~6 months faster — diffusion and capability are separate exponentials ([dwarkesh-dario](../research/notes/dwarkesh-dario.md)).
- Reliability: 95% step ×10 ≈ **60%** end-to-end; 75% single-trial → **42%** pass^3.
- Karpathy: **~Dec 2025** agentic inflection; **decade** of agents; **~10 tok/sec** single-threaded bottleneck.
