# Claude Code Workflows

*How the builders actually work: plan-mode-first, parallel sessions, explore-plan-code-commit, verification loops, slash commands, headless/CI, subagent review, and how much of the code Claude now writes.*

## The thread

Watch enough Anthropic engineers describe their day and one shape emerges: the human has moved up the stack from *typing code* to *orchestrating agents that type code*, and the whole discipline is about closing the loop so a human isn't the thing standing between "looks done" and "is done." Cherny frames the paradigm shift bluntly — programming is becoming "reviewing code rather than handwriting code" ([conversation-on-claude-code](../research/notes/conversation-on-claude-code.md)) — and the numbers back the claim: 70–90% of code at Anthropic is Claude-written (team-dependent), Boris personally reports ~100% on Opus 4.5+ shipping 20 PRs/day, and roughly 4% of *all* public GitHub commits now flow through Claude Code ([yc-inside-claude-code](../research/notes/yc-inside-claude-code.md), [lennys-cherny](../research/notes/lennys-cherny.md)).

The workflow that makes this safe is deceptively simple and repeated almost verbatim across sources: **Explore → Plan → Implement → Commit**. Read first, plan in a mode that can't touch files, gate on the plan's quality, only then write, and verify with a pass/fail signal before committing ([blog-claude-code-best-practices](../research/notes/blog-claude-code-best-practices.md)). Cherny says ~80% of his sessions *start* in plan mode ([yc-inside-claude-code](../research/notes/yc-inside-claude-code.md)). The empirical justification is "context-first → think → act": extended thinking is only useful once Claude has read the relevant code — "thinking in a vacuum" wastes the budget ([conversation-on-claude-code](../research/notes/conversation-on-claude-code.md)).

The frontier of the practice is *removing the human from the loop entirely* on the easy and medium tasks, and the enabling primitive is the **verification loop**. Give the agent a metric plus a way to check itself — write code, run CI, read the errors, fix, repeat — and on Opus 4.7 it will "hill climb" autonomously until it hits the target ([live-coding-cherny-sumner](../research/notes/live-coding-cherny-sumner.md)). This is exactly what "stop babysitting your agents" means: give Claude a way to verify its own work and keep humans out until the work is actually done ([cwc-stop-babysitting](../research/notes/lennys-cherny.md)). Once loops close, the bottleneck stops being code-writing and becomes CI, verification, and finally planning/taste — a progression the builders watch move in real time ([live-coding-cherny-sumner](../research/notes/live-coding-cherny-sumner.md)).

## Patterns

**Explore → Plan → Implement → Commit.** The four-phase default. Plan mode reads without changing anything and gates on plan quality before code is written. Skip planning *only* for typo fixes, log lines, and renames — overhead is only worth it for multi-file, uncertain, or unfamiliar work ([blog-claude-code-best-practices](../research/notes/blog-claude-code-best-practices.md)). See also [orchestration-patterns](orchestration-patterns.md).

**Plan-mode-first.** Frontload planning: ask for 3+ approaches, pick or combine, *then* code. Power users do this to align intent before implementation and cut rework; Boris starts ~80% of sessions here ([conversation-on-claude-code](../research/notes/conversation-on-claude-code.md), [yc-inside-claude-code](../research/notes/yc-inside-claude-code.md)).

**Verification gates.** Use a machine-checkable pass/fail signal — tests, build exit code, linter, diff fixture, screenshot comparison — and demand *evidence*, not an assertion of success. "Without a pass/fail signal, 'looks done' is the only signal, and the human becomes the verification loop" ([blog-claude-code-best-practices](../research/notes/blog-claude-code-best-practices.md)). See [enforcement-reliability](enforcement-reliability.md).

**Self-verification / hill-climbing loop.** Agent writes → runs CI → reads logs → iterates, no human between stages, until an external metric is met. Reliable only on Opus 4.7+; earlier models needed heavy scaffolding ([live-coding-cherny-sumner](../research/notes/live-coding-cherny-sumner.md)).

**Fresh-context / adversarial review.** A separate session (or a second, complementary tool like CodeRabbit) reviews code it didn't write, avoiding same-session confirmation bias. Pair agents with *non-overlapping* strengths — one catches style, one catches edge cases ([blog-claude-code-best-practices](../research/notes/blog-claude-code-best-practices.md), [live-coding-cherny-sumner](../research/notes/live-coding-cherny-sumner.md)). This is exam anti-pattern #9 (same-session self-review).

**Parallel sessions / context-switching.** Run multiple Claude instances against independent workstreams. The scale has climbed steeply: from ~5 parallel sessions early on to "a couple hundred" concurrent agents analyzing GitHub/Twitter/Slack, and "a few thousand overnight," with Boris's PR throughput hitting a record of ~150/day ([acquired-unplugged-cherny](../research/notes/acquired-unplugged-cherny.md), [cherny-sequoia-ascent](../research/notes/cherny-sequoia-ascent.md)). Parallel Claudes even coordinate over Slack during loops. "Context-switching across parallel agent workstreams is becoming the core engineering skill" ([pragmatic-engineer-cherny](../research/notes/pragmatic-engineer-cherny.md), [mad-podcast-cherny](../research/notes/mad-podcast-cherny.md)); enabled by uncorrelated context windows as test-time compute ([yc-inside-claude-code](../research/notes/yc-inside-claude-code.md)).

**Loops (scheduled/recurring agents).** A cron-triggered agent that runs periodically without a human kicking it off — babysitting PRs/CI (auto-rebase, fix flaky tests), clustering feedback every ~30 min. Cherny calls loops "the future"; the management unit becomes dozens of background agents on schedules rather than one attended session ([cherny-sequoia-ascent](../research/notes/cherny-sequoia-ascent.md)). See the "always-on / loop" pattern in [orchestration-patterns](orchestration-patterns.md).

**Auto mode (permission skipping).** A prerequisite for scale: human approval gates break hours-long autonomous runs. "Before this it always got stuck at some kind of permission request." Gate only irreversible actions ([live-coding-cherny-sumner](../research/notes/live-coding-cherny-sumner.md)).

**Task-tier → modality mapping.** Trivial → GitHub Actions (no human), medium → sync terminal (supervised), hard → IDE terminal (live editing) ([conversation-on-claude-code](../research/notes/conversation-on-claude-code.md)).

**Headless / CI.** `claude -p` with `--allowedTools` scoping runs unattended batch jobs; the Issue → Reproduce → Auto-PR pipeline has agents attempt reproduction first and only surface human-reviewable PRs ([blog-claude-code-best-practices](../research/notes/blog-claude-code-best-practices.md), [live-coding-cherny-sumner](../research/notes/live-coding-cherny-sumner.md)).

**Slash commands + CLAUDE.md as reusable memory.** Local slash commands are reusable prompts; CLAUDE.md is decentralized, VCS-shared team memory. "Every time you repeat something, it should probably go in CLAUDE.md" ([live-coding-cherny-sumner](../research/notes/live-coding-cherny-sumner.md), [latent-space-claude-code](../research/notes/latent-space-claude-code.md)). See [memory-and-compounding](memory-and-compounding.md).

**Recovery: `/clear` and `/rewind`.** After 2 failed corrections on the same issue, `/clear` and rewrite beats continued patching. Every prompt is a checkpoint; `/rewind` restores conversation, code, or both ([blog-claude-code-best-practices](../research/notes/blog-claude-code-best-practices.md)).

## Numbers & rules of thumb

- **70–90%** of Anthropic code is Claude-written; **~100%** for Boris on Opus 4.5+; **20 PRs/day** ([yc-inside-claude-code](../research/notes/yc-inside-claude-code.md)); **20–30 PRs/day** via ~5 parallel instances ([pragmatic-engineer-cherny](../research/notes/pragmatic-engineer-cherny.md)).
- **~80%** of Boris's sessions start in plan mode ([yc-inside-claude-code](../research/notes/yc-inside-claude-code.md)).
- **~80%** of Claude Code's own codebase was self-written ([latent-space-claude-code](../research/notes/latent-space-claude-code.md)); **~4%** of all public GitHub commits ([lennys-cherny](../research/notes/lennys-cherny.md), [yc-inside-claude-code](../research/notes/yc-inside-claude-code.md)).
- **2 failed corrections** → `/clear` and rewrite; **8 consecutive Stop-hook blocks** → hard-coded override ([blog-claude-code-best-practices](../research/notes/blog-claude-code-best-practices.md)).
- **~2K tokens / 2 lines** — Boris's CLAUDE.md; prune with "would removing this line cause a mistake?" ([yc-inside-claude-code](../research/notes/yc-inside-claude-code.md), [blog-claude-code-best-practices](../research/notes/blog-claude-code-best-practices.md)).
- **~10% false-positive rate** on Claude Code reviews (~90% signal), usable without full manual review on simple cases ([live-coding-cherny-sumner](../research/notes/live-coding-cherny-sumner.md)).
- **"A couple hundred" concurrent / "a few thousand overnight"** agents; **~150 PRs/day** personal record — the parallel-session ceiling has moved orders of magnitude past the ~5-session era ([acquired-unplugged-cherny](../research/notes/acquired-unplugged-cherny.md), [cherny-sequoia-ascent](../research/notes/cherny-sequoia-ascent.md)).
- **New-hire ramp: weeks → ~2 days**, via Claude Code + declarative skills ("query the database" just works) ([acquired-unplugged-cherny](../research/notes/acquired-unplugged-cherny.md)).
- **Cost inversion:** when implementation cost approaches zero, the bottleneck moves from writing code to architectural decisions and iteration velocity — "the speed of learning becomes the only competitive advantage," and upfront design docs go economically obsolete ([infoq-adam-wolff](../research/notes/infoq-adam-wolff.md)).
- **Underfund headcount, overfund tokens:** deliberately constraining humans while giving abundant tokens forces automation and compounds efficiency — "the more you buy, the more you save" ([acquired-unplugged-cherny](../research/notes/acquired-unplugged-cherny.md)).
- **~15 min** median unsupervised autonomy on some tasks (latent-space era); **~$6/day** internal cost per active user ([latent-space-claude-code](../research/notes/latent-space-claude-code.md)).
- **Skip planning** for typo/log-line/rename; **plan** for multi-file/uncertain/unfamiliar ([blog-claude-code-best-practices](../research/notes/blog-claude-code-best-practices.md)).

## Where speakers disagree

**How durable are these workflows?** Cherny predicts plan mode itself is ~1 month from obsolescence and that general agents will subsume rigid sub-agent role decomposition within 6–12 months — the "bitter lesson" applied to workflow design ([yc-inside-claude-code](../research/notes/yc-inside-claude-code.md), [mad-podcast-cherny](../research/notes/mad-podcast-cherny.md)). Yet the same builders lean hard on *structured* multi-agent review and explicit planning today. The tension is real: today's best practice (scaffold heavily, review adversarially) is explicitly framed as scaffolding the model will outgrow.

**Scaffolding vs. waiting.** Cherny argues non-model scaffolding buys only 10–20% and that waiting for the next model is often the better "engineering" ([yc-inside-claude-code](../research/notes/yc-inside-claude-code.md)). But the live-coding session shows autonomous loops only became possible *because* of concrete scaffolding (CI hooks, monitoring intervals, auto-mode UX) — a bet that some scaffolding is load-bearing right now ([live-coding-cherny-sumner](../research/notes/live-coding-cherny-sumner.md)).

**How much verification is enough?** ~90% review signal is "usable without full manual review" for *simple* cases ([live-coding-cherny-sumner](../research/notes/live-coding-cherny-sumner.md)), but the best-practices doc insists on a hard pass/fail gate before *any* commit ([blog-claude-code-best-practices](../research/notes/blog-claude-code-best-practices.md)). The reconciliation is task-tiering — but where the line sits is a judgment call the sources don't fully settle.

## Interview-ready takes

1. **"The human's job moved from writing to verifying — so the workflow is a verification loop, not a chat."** Explore → Plan → Implement → Commit exists to keep a machine-checkable pass/fail signal between "looks done" and "committed"; without it, the human silently *becomes* the verification loop ([blog-claude-code-best-practices](../research/notes/blog-claude-code-best-practices.md), [conversation-on-claude-code](../research/notes/conversation-on-claude-code.md)).

2. **"Plan-mode-first is the highest-leverage habit."** ~80% of expert sessions start in a read-only plan mode because context-first → think → act beats thinking in a vacuum, and gating on the plan cuts rework before a line is written ([yc-inside-claude-code](../research/notes/yc-inside-claude-code.md), [conversation-on-claude-code](../research/notes/conversation-on-claude-code.md)).

3. **"Never self-review in the same session; pair complementary reviewers."** Fresh-context review avoids confirmation bias (exam anti-pattern #9); the strongest setup pairs agents with non-overlapping strengths (style vs. logic) ([blog-claude-code-best-practices](../research/notes/blog-claude-code-best-practices.md), [live-coding-cherny-sumner](../research/notes/live-coding-cherny-sumner.md)).

4. **"Auto mode and closed verification loops are what unlock parallelism — permission prompts kill it."** Hundred-agent nightly runs and 20–30 PRs/day only work when human approval gates are removed from the hot path and reserved for irreversible actions ([live-coding-cherny-sumner](../research/notes/live-coding-cherny-sumner.md), [pragmatic-engineer-cherny](../research/notes/pragmatic-engineer-cherny.md)).

5. **"Stopping and enforcement must be programmatic, not confidence-based."** Close loops on external metrics (CI pass, test coverage, perf delta) — never on model self-confidence — and encode repeated rules as CLAUDE.md/hooks/lint, because prose can be ignored and hooks cannot ([live-coding-cherny-sumner](../research/notes/live-coding-cherny-sumner.md), [blog-claude-code-best-practices](../research/notes/blog-claude-code-best-practices.md)). See [enforcement-reliability](enforcement-reliability.md).
